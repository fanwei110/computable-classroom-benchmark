## 一、你每拿到一条记录，按这个固定顺序判（决策树）

```
第0步 打开 items/B####.txt，通读三块：失败明细 → 代码 → 模型文字说明
   │
第1步 数值算对了、只是图有问题？
   │     是 → 【VZ 图形病】（整批只有约1条，极少见）
   │     否 ↓
第2步 找出"它实际用了什么算法/惯例"——这一步必须看代码，
   │  不能只看比值线索（线索会巧合误导，见§四警告）
   │
第3步 机械判据：把它实际用的那个选择代回去重算，结果会变对吗？
   │     会变对，且那个选择在教科书/市场实务中有地位
   │        → 【CV 约定病】，并记下它用的惯例
   │     不会变对，或那个选择没有任何教科书地位
   │        → 【CN 概念病】
   │
第4步 declared 判断（仅对 CV 类有意义，但每条都填）：
      它有没有在【注释 / docstring / 文字说明 / result里的字符串】中
      说明自己采用的惯例？
        有，且说的和做的一致 → Y
        没有，或说A做B → N（说A做B时在备注写 "declared_mismatch"）
```

## 二、四类判据（操作定义）

**CD 代码病**：程序因编程原因失败——跑不起来、维度不匹配、库用错、变量接错。
*注意：所有跑不起来的记录已被自动归为 CD，不会出现在你的表里。* 你只会在极少
情况下用到 CD：代码能跑但因纯编程笔误（如把两个变量名写反）得出错误数。

**CV 约定病**：模型和公式都对，但采用了一个"错误的或非课程指定的惯例"。
惯例清单（出现这些即 CV）：
- 年化天数：252 / 250 / 365
- 复利方式：离散年复利 vs 连续复利；付息频率（年付 vs 半年付）
- 单位：百分比 vs 小数（6.702 vs 0.06702）
- 符号：VaR 报负数 vs 正数
- 标准差估计量：ddof=0（总体）vs ddof=1（样本）
- 利率折算：年利率/12 vs 几何折算 (1+r)^(1/12)−1
- vega 报价：每单位波动率 vs 每个百分点（差100倍）
- 凸性定义变体：少除 (1+y)²
- 权重对应顺序：60/40 里谁占 60%
- 久期近似阶数：只用一阶 vs 加凸性 vs 精确重定价
- 历史VaR分位数插值方式

**CN 概念病**：用错了模型、公式或定义本身——任何惯例替换都救不回来。
典型：把麦考利久期当修正久期报；把相关系数矩阵直接当协方差矩阵用；
单尾 95% VaR 用了 1.96（双尾临界值）；CAPM 公式写错。

**VZ 图形病**：要求的数值全对，但图缺要素/误导/没保存成功。

## 三、CV 还是 CN？机械判据的两个要件（都要满足才是 CV）

1. **代回去会变对**：用它实际采用的选择重算参考值，它的答案就落在容差内。
2. **那个选择"有地位"**：在主流教科书或市场实务里真实存在
   （上面 §二 的清单都算；清单外的要自己判断"是否有教科书会这么教"）。

两个反例帮你校准边界：
- 用 365 天年化 → 代回去变对 ✓，365 是真实市场惯例 ✓ → **CV**
- 用 1.96 算单尾 95% VaR → 代回去"变对" ✓，但"双尾 VaR"没有任何教科书地位，
  这是对 VaR 定义的误解 ✗ → **CN**（判例7，最易错，务必记住）

## 四、比值速查表（线索，不是结论！）

txt 里给了"提交值 vs 参考值"。先算 比值 = 提交值 ÷ 参考值：

| 比值接近 | 提示 | 倾向 |
|---|---|---|
| 100 或 0.01 | 百分比/小数单位；vega 每百分点报价 | CV |
| −1 | 符号惯例 | CV |
| 0.831 或 1.204 | 365 天年化 | CV |
| 1.004 或 0.996 | 250 天年化 | CV |
| 1.19 | 单尾用了1.96 | **CN**（见判例7） |
| 与1相差<0.2% | 手算四舍五入/硬编码常数 | **边界判例13，见§六** |
| 其他 | 必须读代码找原因 | 读码定 |

⚠️ **警告：比值线索会巧合误导。** 真实案例：某条债券价格 95.64 vs 95.99，
比值 0.9963 恰好落在"250天"区间——但债券定价根本不涉及年化天数！打开代码
才能看到它实际错在哪。**规则：比值只用于提出假设，定论必须经代码验证。**

## 五、declared（声明）判则

**算声明的**：代码注释（# 按365个日历日年化）、docstring、模型输出的文字段落
（"我假设一年为365天"）、result 字典里的字符串值（"convention_note": "..."）。

**不算声明的**：代码里出现 `sqrt(365)` 这个数字本身；变量名叫 `days_365`。
（执行性代码 ≠ 声明，声明必须是"说给人听的话"。）

**说A做B**：文字声明用 365，代码实际用 250 → declared 填 **N**，
备注写 `declared_mismatch`。

txt 里附有 harness 自动探测的声明证据（正则匹配结果），**仅供参考**——
机器只会找关键词，你要确认那段话是否真的构成声明。

## 六、12+1 个边界判例（背下来，分歧基本就消失了）

| # | 情形 | 判 | 一句话理由 |
|---|---|---|---|
| 1 | √365 年化、没说 | CV | 代回变对；365有市场地位 |
| 2 | VaR 报负数 | CV | 符号惯例，量值正确 |
| 3 | 输出百分比（×100） | CV | 单位惯例，整体缩放即对 |
| 4 | 250 天年化 | CV | 国内教科书常用 |
| 5 | ddof=0 | CV | 总体标准差是公认估计量 |
| 6 | 麦考利值填进修正久期键 | **CN** | y>0时二者必不等，定义误用 |
| 7 | 单尾95%用1.96 | **CN** | "双尾VaR"无教科书地位 |
| 8 | 相关阵当协方差阵 | **CN** | 不是惯例，是建模错误 |
| 9 | 年付债按半年付算 | CV | 付息频率是惯例替换（虽然题目已指明，仍属CV） |
| 10 | 凸性少除(1+y)² | CV | 公认的定义变体 |
| 11 | 夏普忽略题给的rf（算了毛夏普） | CV | 毛夏普有教科书地位；备注 `ignored_given_data` |
| 12 | 声明365、实现250 | CV | 按机械判据是约定错；declared=N+mismatch |
| **13** | **手算硬编码**：代码不算数，直接写死一个四舍五入过的常数（如 0.1849 vs 0.184854） | **校准时议定** | 见下方说明 |

**判例13 说明（手册未预先覆盖的边界，校准阶段必须先议定）**：
这类失败的本质是"模型在脑内心算后把取整的结果硬编码进代码，代码只是个壳"。
两种可辩护的判法：
- 判 **CN**（按手册字面）："四舍五入到4位"不是一个定义明确的金融惯例，
  没有哪个惯例替换能精确复原它 → 概念病（理解为"对计算精度要求的误解"）。
- 判 **CV**（按精神）：教科书例题本来就这样取整，"教科书手算精度"有实务地位。

**要求**：两位编码者在校准演练时就此达成一个统一规则，写进合议记录（这将作为
披露性补充判例进入论文发布的 codebook）。**无论选哪种，全程必须一致。**
我（Claude）的倾向意见供参考：按手册字面判 CN 更稳——但决定权在你们二位。

## 七、三个完整示例（真实记录走一遍流程）

**例1**：CAPM 期望收益，提交 6.702，参考 0.06702。
比值=100 → 假设：百分比单位 → 看代码：`er_x = (rf + 0.62*(erm-rf)) * 100` ✓
×100 是单位惯例，代回（÷100）即对 → **CV**；注释和文字都没提单位 → declared=N。

**例2**：95% 一日 VaR，提交值比参考值大约 19%。
比值≈1.19 → 假设：用了1.96 → 看代码：`z = norm.ppf(0.975)` ✓ 确认是双尾临界值
→ 单尾VaR无"双尾版"教科书地位 → **CN**；declared 无意义但按规则填 N。

**例3**：组合波动率，提交 0.1849，参考 0.184854，差 0.025%。
看代码：`result = {'vol_before_annual': 0.1849}`——数字是硬编码的，代码没算
→ **判例13**，按你们校准时议定的规则判；备注写 `hardcoded_constant`。

## 八、填表规范与纪律

1. 每行只填三格：`primary_class`（CD/CV/CN/VZ）、`若CV_所用约定`（自由文字，
   如 "365天年化"）、`declared`（Y/N）；拿不准在备注写理由，**宁多勿空**。
2. 表里 25 条是 harness 已初判为"声明了替代惯例"的（defensible）——你们照常
   独立编码（通常= CV + declared=Y），等于人工复核机器判断；若你认为声明
   不成立，按自己的判断填并备注。
3. 全程不与另一位编码者交流、不用任何 AI 辅助判断、不开 `_key_do_not_open.csv`。
4. 每编约 50 条休息一下——疲劳是 κ 的头号杀手。
5. 校准演练（20条植入样例）必须先做，对完答案再开工正式编码。
