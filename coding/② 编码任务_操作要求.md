# 错误编码任务 · 操作要求（照着做即可）

> 先读过《① 编码任务_说明.md》再开始。本文件是一步步的操作清单。

## 〇、需要用到的文件（都在本文件夹 `coding/` 里）

| 用途 | 文件 |
|---|---|
| **你要填的表** | 编码员 A → `coder_A.xlsx`；编码员 B → `coder_B.xlsx`（两张表内容相同，各填各的） |
| **每条的完整材料** | `items/<blind_id>.txt`（例如 `items/B0001.txt`） |
| **判据手册**（决策树 + 四类定义 + 13 个判例 + 3 个完整示例） | `判别手册_中文版.md`、`../codebook.md` |

| 🚫 **绝对不要打开** | `_key_do_not_open.csv` |

## 一、表格里你要填的列（只填这 4 列）

| 列名 | 填什么 |
|---|---|
| `primary_class(CD/CV/CN/VZ)` | **四选一**，填主错误类（大写字母：CD/CV/CN/VZ） |
| `若CV_惯例约定(可留空)` | 若判 CV，简写用错了哪个惯例（如"365天""百分比""ddof"）；不是 CV 就留空 |
| `declared(Y/N)` | 该生成是否声明了所用惯例，填 Y 或 N |
| `备注` | 拿不准的理由、你的判断依据（鼓励多写） |

> `blind_id`、`task_id`、`失败摘要` 等列**已经给好了，不要改动**。

## 二、第一步 · 校准演练（两人都必须先做）

1. 各自**独立**打开 `calibration/drill_sheet.xlsx`，对 20 个样本判类（样本材料在 `../harness/adversarial/planted/`）。
2. 全部填完后，**再**打开 `calibration/answer_key.csv` 对答案。
3. 分歧的地方，两人对照 `判别手册_中文版.md` 讨论，直到理解一致。
4. **目标：20 题达成一致理解后，再进入正式编码。**（这一步是为了让两人对四类判据"校准到同一把尺子"。）

## 三、第二步 · 正式编码（各自独立完成 286 条）

对你表里的**每一行**，重复以下动作：

1. 看这一行的 `blind_id`（如 `B0001`），打开 `items/B0001.txt`。
2. txt 里有四块内容：
   - **要求的输出项**（这道题该算出什么）
   - **判分失败明细**：`提交值 vs 参考值`（关键线索）
   - **提取到的代码**（模型写的 Python）
   - **模型的完整文字说明**（用来判 `declared`）
3. 按《说明文档》第三、四节判 `primary_class`：
   - 先看是不是 VZ（图对不对）或 CD（代码本身坏没坏）；
   - 主要在 **CV vs CN** 之间抉择——用"黄金判据"：把它实际用的惯例代回重算，变对→CV，仍错→CN；
   - **务必打开代码确认**，比值只是线索。
4. 判 `declared`（Y/N）：只看注释/文字说明/字符串。
5. 若是 CV，在"若CV_惯例约定"列简写惯例名；拿不准的写"备注"。
6. 把结果填回表里这一行。

> 顺序：把表里全部 **286 行（批次 1，优先）** 做完即可。若后续需要更大样本，我会再给批次 2。

## 四、纪律（再强调一遍，很重要）

- 全程 **两人不交流、不用任何 AI 工具**；
- **不打开** `_key_do_not_open.csv`；
- 拿不准**写备注**，不空着猜。

## 五、第三步 · 交回

把两张填好的 `coder_A.xlsx` 和 `coder_B.xlsx` **发回给范老师**。

之后由范老师这边自动完成：
- 计算 **Cohen's κ、Gwet's AC1、人工-vs-自动一致率**（论文要报告的信度数字）；
- 生成一份**分歧清单**（只列出 A、B 判得不一样的条目）。

两位编码员**只需就"分歧清单"里的条目再合议一次、定出最终标签**即可——已经一致的不用再看。

## 附 · 三个上手示例

**示例 1（CV，惯例病）**
- 失败明细：`capm_return_monthly: 提交值 -8.4005 | 参考值 -0.084005`
- 比值 ≈ ×100 → 提示"百分比 vs 小数"。打开代码确认：CAPM 公式**用对了**，只是把结果按百分数（-8.4%）而非小数（-0.084）填了。
- 判定：`primary_class = CV`，`若CV_惯例约定 = 百分比/小数`，`declared` 看有没有注明单位。

**示例 2（CN，概念病）**
- 代码用了**错误的公式/模型**（例如久期该用麦考利却用了修正，或把 VaR 的分位数取反用错）。把任何惯例代回去都救不回来。
- 判定：`primary_class = CN`。

**示例 3（declared 判断）**
- 代码里有注释 `# 按 252 个交易日年化` → `declared = Y`。
- 代码里只是出现了数字 `252`、没有任何文字说明 → `declared = N`。

（更多完整判例见 `判别手册_中文版.md`。）
